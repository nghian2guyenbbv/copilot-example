LangGraph4j Incident-Response Agent

Ứng dụng Spring Boot 3 / Java 17 / Maven, trong đó một AI agent nhận cảnh báo hệ thống (ví dụ: "High CPU and connection pool exhaustion on payment-service"), điều tra, lập kế hoạch khắc phục, tạm dừng chờ con người phê duyệt trước bất kỳ lệnh nguy hiểm nào, thực thi bản vá rồi kiểm tra lại sự phục hồi theo vòng lặp. Trạng thái và dữ liệu được lưu trong Microsoft SQL Server (Docker Compose).

3. Agent graph

START→ dispatch→ fan-out →
lookup_history lookup_runbooks scan_metrics
→ fan-in → decide (LLM)→ approval_gate ⏸ INTERRUPT→ execute→ verify→ END
  • Điều tra song song: ba node lookup chạy trong cùng một superstep, mỗi node ghi vào một key state khác nhau và tạo audit row riêng.
  • Định tuyến theo rủi ro: sau decide, rủi ro HIGH đi qua approval_gate; LOW/MEDIUM đi thẳng tới execute.
  • Human in the loop: graph được compile với interruptBefore("approval_gate"). Graph dừng lại, lưu state và chờ. Nếu bị từ chối, incident kết thúc mà không thực thi gì.
  • Vòng lặp thử lại: nếu verify thấy hệ thống vẫn chưa khỏe, graph quay lại dispatch (tối đa 3 lần, sau đó ESCALATED). Kế hoạch nguy hiểm mới sẽ yêu cầu phê duyệt lại.

RemediationStepRecord serializable: command, dangerous, reason. Phải serializable để được checkpoint.

Khóa chính dùng IDENTITY của SQL Server. Bốn interface *Repository là Spring Data JPA repository. IncidentTools cung cấp các tool cho agent là queryActiveIncidents() và fetchServiceMetrics(service), đọc dữ liệu thật từ DB.

8. Checkpoint bền vững (SqlServerCheckpointSaver)

  • Kế thừa AbstractCheckpointSaver của LangGraph4j và lưu mỗi checkpoint thành một dòng trong lg_checkpoints (state được serialize vào NVARCHAR(MAX)).
  • Tự tạo bảng khi khởi động nếu chưa có.
  • Mỗi lần insert/update/delete chạy trong một transaction JDBC riêng (commit hoặc rollback), nên crash không để lại checkpoint ghi dở.
  • Vì state nằm trong database, incident đang tạm dừng vẫn sống sót qua lần khởi động lại ứng dụng và có thể tiếp tục bằng cách phê duyệt sau đó.
  • Graph được compile với releaseThread(false) để state cuối cùng vẫn đọc được sau khi chạy xong.

9. Service và REST API

IncidentService lưu alert, seed môi trường giả lập, chạy graph (tiêu thụ stream đến khi END hoặc interrupt), áp dụng quyết định của con người bằng updateState, tiếp tục bằng GraphInput.resume() và đồng bộ trạng thái cuối về dòng Alerts.

MethodĐường dẫnMô tả
POST/incidentsBody {"serviceName","message"}. Chạy đến khi xong hoặc dừng chờ phê duyệt.
POST/incidents/{id}/approvalBody {"approved":true|false}. Trả 409 nếu incident không ở trạng thái chờ.
GET/incidents/{id}Trạng thái hiện tại, findings, plan, timeline, awaitingApproval.
GET/incidents/{id}/auditAudit trail lấy từ database.

Kịch bản điển hình

1. POST /incidents                -> lần 1: SCALE_OUT (LOW) tự chạy, hệ thống vẫn chưa khỏe
                                    lần 2: KILL_IDLE_SESSIONS (HIGH) -> tạm dừng, awaitingApproval=true
2. POST /incidents/{id}/approval  -> thực thi; rò rỉ làm đầy lại pool -> lần 3: RESTART_SERVICE (HIGH) -> dừng lần nữa
3. POST /incidents/{id}/approval  -> restart xóa rò rỉ -> verify OK -> trạng thái RESOLVED

10. Cấu hình và Docker

  • docker-compose.yml: service mssql (SQL Server 2022, healthcheck, volume bền vững mssql_data, cổng host mặc định 1434 qua MSSQL_PORT) và mssql-init chạy một lần để tạo sag khi DB đã healthy.
  • application.yml: JDBC URL với encrypt=true;trustServerCertificate=true, kích thước pool Hikari, ddl-auto: update, incident.max-attempts và cấu hình LLM (base-url, api-key, model).
  • Biến môi trường ghi đè: MSSQL_HOST, MSSQL_PORT, MSSQL_SA_PASSWORD, OPENAI_API_KEY. Mật khẩu SA mặc định chỉ dành cho môi trường phát triển cục bộ.

11. Kiểm thử (IncidentFlowTest)

  • Vòng lặp đầy đủ có phê duyệt: dừng lại, có dòng checkpoint, duyệt hai lần, kết thúc RESOLVED, audit hiển thị cả ba hành động đã thực thi.
  • Từ chối: lệnh nguy hiểm không bao giờ được thực thi và phê duyệt thêm sẽ trả lỗi.
  • Nhánh song song: cả ba node lookup đều ghi audit row.

Đây là integration test nên cần container SQL Server đang chạy.

Hạn chế

  • Các hành động hạ tầng chỉ là giả lập; hãy thay SimulatedEnvironment bằng executor thật khi dùng production.
  • LangGraph4j không có API Send, nên song song hóa được thực hiện bằng nhiều edge đi ra.
  • Đường OpenAI chưa được kiểm thử vì không có API key; chưa có stress test về deadlock.
